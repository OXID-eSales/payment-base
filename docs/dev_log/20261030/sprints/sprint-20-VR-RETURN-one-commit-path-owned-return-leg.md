## Design

| Piece | One job |
|---|---|
| payment-base `Checkout\Return\ReturnAccessGuard` | the one check in front of every return leg: contract exists, `provider` = caller's provider, valid `ContractReturnToken` **or** (session user = contract user **and** `initiating_session_id` matches). Unknown ownership ⇒ reject. Used by `CheckoutReturnResponder::respond()` and the headless `…CheckoutReturn` mutations. |
| payment-base `Checkout\Return\ContractReturnTokenService` | one token service (replaces Stripe + Mollie copies): HMAC over `contractId|exp|userId?` with its own secret (`oe_payments_secrets`, generated by migration), `exp` default 24 h. Old tokens accepted for one release behind a kill-switch setting, then removed (no permanent fallback). |
| payment-base `CheckoutReturnResponder` | no longer dispatches `PaymentAuthorizedEvent`; delegates to `ContractCommitService::commit(PaymentConfirmation)`. Resolvers must put **PSP-reported** amount + currency into `ReturnResolution` (a resolver that only knows the contract amount must fetch it from the PSP). |
| payment-base `ContractService::extractTotals()` | `ShopCurrency::codeOf()` (throws), parameter typed `Basket`; `totalGross <= 0` ⇒ `ContractCreationRefused` unless the payment type allows zero. |

## Definition of done

Every provider's return leg passes `ReturnAccessGuard` and commits only through `ContractCommitService`
(grep: no `PaymentAuthorizedEvent` dispatch outside `ContractCommitService`). No `'EUR'`/`0.0` default in contract
creation. Reports + consumer test counts in `done/`.

## Risks

R3 changes return URLs: shoppers mid-checkout during deploy hold old tokens ⇒ legacy-token switch for one release.
R2 deletes a public controller method: verify no theme/plugin calls it (grep peroxid / oxid-fe-*).
